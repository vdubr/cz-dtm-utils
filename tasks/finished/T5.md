# T5 — Router parseru — ✅ hotovo

## Co se udělalo
- **`src/router.ts`** — verzní router (R3/R4):
  - `parseJvfDtm(xml)` — **stejná signatura** (R3); dispatch dle R4:
    (1) `ServisJVFDTM` → chyba s odkazem na `parseErrorProtocol` (T6),
    (2) `VerzeJVFDTM` ∈ `SUPPORTED_VERSIONS` → daná větev,
    (3) neznámá/chybějící verze → strukturní sniff (druh `ZaznamObjektu`),
    (4) fallback `DEFAULT_VERSION` + warn. Nikdy nespadne na detekci.
  - `getEntityCatalog(version)` — katalog dle verze (1.4.3 / 1.5.0.1).
  - Pomocné exporty: `resolveDtmVersion`, `detectVersionString`,
    `sniffVersionByStructure`, `isErrorProtocolXml`.
  - Detekce lehká (regex nad raw XML, bez dvojího plného parsu).
- **`src/index.ts`** — router napojen; `parseJvfDtm` z routeru přebíjí
  1.4.3 verzi. `ENTITY_CATALOG` (=1.4.3) zůstává pro zpětnou kompatibilitu.
  - Pozn.: pořadí `export *` (1.4.3) **před** explicitním re-exportem routeru
    je záměrné — bundler (esbuild/vite) volí „last-wins", Node ESM dává navíc
    přednost explicitnímu re-exportu vždy → router vyhrává ve všech konzumentech
    (vitest, Vite build vieweru, Node). Ověřeno i nad built `dist/`.
